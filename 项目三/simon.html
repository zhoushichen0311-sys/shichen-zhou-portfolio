Simon Says

社区生活激励系统 · Community Life-Incentive OS

一个把「工作时长」变成「生活品质」的社区超级 App：输入用户画像与本周工时，系统按激励规则累积权益、调度 POI 线下资源，输出可解锁的生活等级与专属服务。

背景 / CONTEXT

996 让年轻 IT 打工人「住得进，却留不下」

大量来自小城市的程序员涌入一线城市，长期处在 996 与「35 岁被裁」的压力下。他们住在十几平米的出租屋里，邻里互不相识，难以找到有共同点的「群体」，逐渐产生「不在家」的漂泊感。设计的出发点，是先把这群人的真实痛点梳理清楚，再决定产品去解决什么。

时工作压力

长期 996，早出晚归，生活被工作填满，节奏单调。

归缺乏归属

异乡漂泊，租住十余平米，邻里互不相识。

心心理服务缺口

焦虑与倦怠长期累积，却无处安放与疏导。

闲休闲配套不足

下班后缺少可去、可社交的公共空间。

用户分层画像 / USER PERSONAS

三层用户，三种需求优先级

按「初来 → 适应 → 危机」把目标用户分成三层，梳理各自的核心痛点与需求优先级，用来划定产品的服务边界——先满足谁、先做什么。

系统整体架构 / SYSTEM ARCHITECTURE

用户端 × 后台管理端，一套闭环系统

系统拆成「前端用户端」与「后台管理端」两套模块：用户端负责体验与上报，管理端负责规则、调度与结算，两者围绕激励闭环协同。

核心机制 / INCENTIVE LOOP

工作时长累积 → 权益兑换 → 生活品质升级

这是产品的核心闭环，也是一条清晰的 Input → Process → Output 流程：把用户投入的工时转化为可量化的权益，再兑换成实际的生活品质提升，升级后重新计入下一轮，形成正向循环。

INPUT · 输入01

工作时长累积

用户在办公区投入的工作时长被记录进个人账户，构成激励系统的原始输入。

例：本周投入 42h → 记入账户
→
PROCESS · 处理02

权益兑换

按激励规则把工时换算成积分，再经 POI 资源调度，决定可兑换的服务与配额。

规则：1h ≈ 8 积分 · POI 按配额发放
→
OUTPUT · 输出03

生活品质升级

兑换结果落到真实生活：更大的房型、更多 POI 权限与专属服务，构成可感知的输出。

结果：解锁双人房 + 咖啡厅 POI
↻ 升级后的状态重新计入下一轮工时考核 —— 闭环正向驱动用户行为

用户旅程 / USER JOURNEY

小明的入住旅程：机制如何影响每一步决策

以小明为例展示入住体验

STEP 1迷茫
明 初到城市 · 收到社区传单
“刚毕业来到大城市，这里和老家差距好大，我甚至找不到归属感。”
决策→ 留意传单
STEP 2心动
明 参观社区 · 被福利吸引
“共享客厅、心理咨询室、还能升级房间…这里功能好多，我想住进来！”
决策→ 申请入住
STEP 3期待
明 入住登记 · 领取工时任务
“原来工作能换工时，工时能换更好的生活，那我努力一点就好了。”
决策→ 开始打卡
STEP 4满足
明 累积兑换 · 房间与 POI 升级
“工时攒够了！换到了双人房，还解锁了咖啡厅，生活好像真的变好了。”
决策→ 持续兑换
STEP 5疑惑
明 察觉异样 · 机制的两面
“为什么这个房间不太一样？也许「自由」的选择，一直在被悄悄引导。”
决策→ 重新审视
设计洞察

旅程图不只展示「体验有多好」，更揭示激励闭环如何在每个决策点引导用户——这正是项目从空间批判转化为产品思考的落点。
